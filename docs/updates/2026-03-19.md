# Update Log - 2026-03-19

## Context

Server-side `train_acc8_amp_structured` failed in multi-GPU mode after brightness stats stage.

Observed root error:

- `AttributeError: 'DistributedDataParallel' object has no attribute 'obs_encoder'`

## Root Cause

`freeze_encoder` path in training loop accessed:

- `self.model.obs_encoder.eval()`
- `self.model.obs_encoder.requires_grad_(False)`

Under DDP, `self.model` is wrapper object and does not expose `obs_encoder` directly.

## Fix Applied

Switched freeze-encoder epoch logic to unwrapped model in:

1. `diffusion_policy/workspace/train_diffusion_unet_timm_workspace.py`
2. `diffusion_policy/workspace/train_diffusion_transformer_timm_workspace.py`
3. `diffusion_policy/workspace/train_diffusion_unet_image_workspace.py`

New behavior:

- uses `unwrapped_model = accelerator.unwrap_model(self.model)`
- applies freeze via `unwrapped_model.obs_encoder.*`

## Notes

1. The `numpy` cast warning shown during brightness stats is non-fatal.
2. The training abort in the provided logs is caused by the DDP freeze-encoder attribute error.

## Metric Consistency Fix (Frozen ViT Analysis)

Observed concern:

1. train head-mask importance and val head-mask importance looked inconsistent.

Root issue:

1. in `train_diffusion_unet_timm_workspace.py`, train MSE used first 10 action dims
2. val MSE used full action dims, causing train/val head-importance to be non-comparable

Fix:

1. unified val MSE/no-head/importance to use same first-10 action slice as train
2. added optional full-dim diagnostics:
   - `val_action_mse_error_full`
   - `val_action_mse_error_no_head_full`
   - `val_action_mse_head_importance_full`

## Head-Importance Stability Fix (Diffusion Sampling Noise)

Additional finding:

1. head-mask importance compares two separate `predict_action` calls
2. diffusion inference is stochastic, so if each call uses different noise seed,
   `importance` includes random sampling noise instead of pure head-information effect

Fix:

1. added optional `generator` argument to:
   - `diffusion_unet_timm_policy.py::predict_action`
   - `diffusion_transformer_timm_policy.py::predict_action`
2. workspace metric path now uses same seed for masked/unmasked pair per epoch:
   - train pair seed: `base + epoch * 2`
   - val pair seed: `base + epoch * 2 + 1`
3. added optional config override:
   - `training.head_importance_eval_seed` (defaults to `training.seed`)
4. UNet train-side sampling metric now uses latest batch of current epoch
   (previously pinned to first-ever batch), reducing overfitted metric bias
